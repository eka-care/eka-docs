---
description: Generate a product's integration plugin skeleton from its documentation pages
argument-hint: <product-slug>
---

Scaffold `plugins/<product-slug>/` from the product's pages. Load `product-plugins` and `docs-strategy`. Arguments: $ARGUMENTS

1. Run `npm run docs:check <slug>`. If the product has `ladder` or `workflow` failures, stop: a plugin built from an incomplete ladder encodes the gaps. Say which pages are missing.
2. Read every page of the product: overview, journeys, workflows (frontmatter and all seven sections), webhooks, errors, testing. Read `api-sdk/auth/getting-started.mdx`.
3. Create the layout in `product-plugins`: `.claude-plugin/plugin.json` (name is the slug, description from the overview's `description`, keywords from the audiences), `README.md` with the two install commands and a table of skills and commands, one skill per workflow page, the overview, auth, testing and debugging skills, the debugger agent, one `integrate-<workflow-slug>` command per workflow.
4. Each generated file starts with `<!-- generated by /plugin-scaffold from <page url> -->`. Each workflow skill carries the page's shape (call order, decisions, state, failure codes) and the reference URLs to fetch before each call, and no request or response body. The description line of each skill is written for triggering: what the user says that means they need it.
5. Add the plugin to `.claude-plugin/marketplace.json` at the repo root.
6. Run `claude plugin validate ./plugins/<slug> --strict` and fix whatever it reports. Check that no skill shares a name with a command.
7. Report the files, then hand off: the plugin is a skeleton until the `integration-tester` agent has run each workflow against sandbox. Say that, and name the first workflow to test.
