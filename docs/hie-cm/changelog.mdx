<Update label="October 13, 2026" description="October 13, 2026" tags={["Docs"]}>

## Added

- **Journeys and workflows for every flow.** Seven journeys describe who uses ABDM Connect and why, from registering a walk-in patient to fetching records with consent. 23 workflows give the call order for each step, the fields to carry between calls, what to store, and what to do when a call fails. Start from the [Overview](/api-sdk/hie-cm/overview) or the [Quickstart](/docs/hie-cm/quickstart).
- **Webhook events in the spec.** The OpenAPI spec now describes the 18 webhook events Eka sends you, such as `abha.created` and `abha.consent_update`. See [Webhooks](/docs/hie-cm/webhooks) for when each fires and which workflow handles it.
- **Consent PIN reference pages.** Each consent PIN operation has its own page, for example [Consent pin set](/api-sdk/hie-cm/consents/pin/set) and [Consent pin reset](/api-sdk/hie-cm/consents/pin/reset).
- **ECDH reference pages.** [Ecdh keys](/api-sdk/hie-cm/care-contexts/ecdh/keys), [Ecdh encrypt](/api-sdk/hie-cm/care-contexts/ecdh/encrypt) and [Ecdh decrypt](/api-sdk/hie-cm/care-contexts/ecdh/decrypt) each have a page.

## Changed

- **Operation ids and tags.** Every operation in the spec now has an `operationId` and tags. If you generate a client from the spec, regenerate it to pick them up.
- **Order status pages.** [Order Status](/api-sdk/uhi/phys-cons/order-status) and [Get Order Status](/api-sdk/uhi/phys-cons/get-order-status) now document `POST` and `GET` `/abdm/uhi/v1/physical-consultation/booking/order-status`, the path the spec defines. They previously showed `/booking/status`. If you built against that path, switch to `/booking/order-status`. {/* TODO: confirm: whether /booking/status was ever served, so integrators know whether they must change anything. */}
