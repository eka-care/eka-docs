# Solutions, Integrations, Resources Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reorganise developer.eka.care into three families (Solutions, Integrations, Resources), give every product a Build with AI section, and ship one reference skill per product generated from its API pages.

**Architecture:** The navigation is rebuilt by `scripts/build-nav.py`, never edited by hand. A new `regroup()` step runs on the already-built tree, renames and moves families, items and groups, and leaves every page in place exactly once. A new `scripts/build-skills.mjs` reads each product's "APIs & SDKs" tab from `docs.json` and the OpenAPI specs its pages point at. It writes one plugin per product under `plugins/eka-<slug>/`. The landing page (`landing/source.html` → `snippets/landing.jsx`) follows the new families.

**Tech Stack:** Mintlify (`docs.json`, MDX), Python 3 (build-nav), Node 22 ESM with `yaml` and `gray-matter` (build-skills, tests via `node --test`), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-21-solutions-integrations-resources-design.md`

## Global Constraints

- Families, in order: `Solutions`, `Integrations`, `Resources`.
- Solutions items, in order: `Scribe`, `Document Parsing`, `Agents`, `Medical Knowledge`, `Patient Experiences`, `ABDM Connect`, `NHCX`, `UHI`.
- Integrations items, in order: `Overview`, `Eka EMR`, `IPD`, `Billing`, `Health Records`.
- Resources items, in order: `Get started`, `Auth`, `Webhooks`, `Encryption`, `SDKs`, `All APIs`, `Research`, `Changelog`.
- Item tabs: `Documentation`, `APIs & SDKs`, `Changelog`. There is no `Cook Book` tab and no `Release Notes` tab.
- Product sidebar order: Overview, Get started, Guides, Webhooks, Build with AI, Resources. A section with nothing in it is left out.
- Every page listed in `docs.json` today appears exactly once afterwards.
- Every moved URL gets a `permanent: true` redirect in `docs.json` and an entry in `scripts/route-map.json`.
- URLs stay put for `docs/models/*`, `docs/datasets/*`, `docs/hie-cm/*`, and Spotlight.
- Page rules come from the eka-docs-contributor plugin: word budgets (overview 600, others 700), sentences under 35 words, no em dashes, an icon on every sidebar row.
- No "coming soon" rows anywhere.
- The ABDM Connect MCP server and plugin are labelled "covers M1 only for now".
- The DPDP and India-hosted line is **not** shipped. It is an open item.
- Generated files start with `generated by scripts/build-skills.mjs` and are byte-identical across runs.

## Review Focus

1. **`regroup()` drops or duplicates a page.** The page multiset before must equal the page multiset after, on every run, not only on the legacy path. This is pinned in Task 1.
2. **A moved or renamed URL 404s.** Every source path in the move list must resolve to a redirect, and every redirect destination must exist as a file. This is pinned in Task 2.
3. **A bare `openapi: METHOD /path` matches more than one spec.** The skill would describe the wrong operation. Resolve the way Mintlify does (alphabetically first spec that has it) and report each ambiguity. This is pinned in Task 3.
4. **The generator gives different bytes on two runs.** CI's drift check would then flake. No timestamps, sorted keys and sorted operations. This is pinned in Task 3.
5. **The landing journey goes blank because its `GROUPS` still name old families.** Every `GROUPS` entry must resolve in `J`. This is pinned in Task 6.
