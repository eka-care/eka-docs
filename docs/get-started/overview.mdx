Every Eka product uses the same keys and the same access token. Get them once, then build with any product: the scribe, records, agents, models or ABDM.

## Get your API keys

<Steps>
  <Step title="Create a client in the console">
    Sign in to the [Eka Care console](https://console.eka.care) and create a client. You get two values.

    <CardGroup cols={2}>
      <Card title="Client ID" icon="id-card" href="/api-sdk/auth/client-login">
        Identifies your application to Eka's APIs.
      </Card>
      <Card title="Client Secret" icon="key" href="/api-sdk/auth/client-login">
        A confidential key, like a password, used with the client ID.
      </Card>
    </CardGroup>
  </Step>
  <Step title="Building for doctors or patients?">
    Integrate Eka accounts with OpenID Connect (OIDC), or ask the healthcare provider for an API key from their [workspace](https://hub.eka.care/account/account/apitoken/).
  </Step>
  <Step title="Set up your client">
    Send every request to `https://api.eka.care`. Any HTTP client works: Postman, cURL or the library for your language.
  </Step>
</Steps>

<Note>
  For keys or help, write to [ekaconnect@eka.care](mailto:ekaconnect@eka.care).
</Note>

## Authenticate

<Steps>
  <Step title="Get an access token">
    Call [client login](/api-sdk/auth/client-login) with your client ID and client secret. You get an access token and a refresh token.
  </Step>
  <Step title="Send it with every request">
    Put the access token in the `Authorization` header of each API call.
  </Step>
  <Step title="Refresh it when it expires">
    The access token lasts about 30 minutes. A `401 Unauthorized` means it has expired: call [refresh token](/api-sdk/auth/refresh-token-v2) for a new one.
  </Step>
</Steps>

For server-to-server work that should not refresh every half hour, use a [long-lived token](/api-sdk/auth/getting-started#long-lived-access-token).
