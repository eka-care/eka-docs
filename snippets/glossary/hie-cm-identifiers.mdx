| Term | What it means | Where it is used |
|---|---|---|
| OID (Eka user ID) | Eka's ID for a patient, returned as `eka.oid` when an ABHA is created or the patient logs in. You send it in the `X-Pt-Id` header or the `oid` query parameter on later calls. | [ABDM Connect overview](/api-sdk/hie-cm/overview#common-headers) |
| Partner patient ID | Your own ID for the patient, sent in the `X-Partner-Pt-Id` header. | [ABDM Connect overview](/api-sdk/hie-cm/overview#common-headers) |
| HIP ID | The ID of the facility a call is made from, sent in the `X-Hip-Id` header. On NHCX calls it selects the facility that raises the claim. | [ABDM Connect overview](/api-sdk/hie-cm/overview#common-headers) |
| `txn_id` | The transaction ID that the first call of an OTP or linking flow returns. You send it back on every later step of that flow. | [ABDM Connect overview](/api-sdk/hie-cm/overview#multi-step-flows) |
| `skip_state` | A field in the Aadhaar OTP verify response that tells you the next call. Its values are `confirm_mobile_otp`, `abha_create` and `abha_select`. | [Create an ABHA with Aadhaar OTP](/docs/hie-cm/workflows/create-abha-aadhaar-otp) |
| `source_error` | The part of an ABDM Connect error body that carries ABDM's own code when the gateway refuses a call, such as `ABDM-1010`. | [Errors](/docs/hie-cm/errors) |
