Create a sandbox ABHA from these docs in about ten minutes, without writing code. Every step runs from the **Try it** playground on its API page.

## In short

- Get an access token once, then paste it into the **Bearer** field of each playground.
- Six calls: log in, send the Aadhaar number, verify the OTP, pick an address, check it is free, create the ABHA.
- You end with a 14-digit ABHA number, an ABHA address and Eka's patient id, `eka.oid`.
- There is no encryption step. You send the Aadhaar number as plain text and Eka handles ABDM's encryption for you.
- This page walks one case: the patient has no ABHA, and the mobile you send is the one linked to their Aadhaar.

## Before you start

- **Sandbox credentials.** Create an Eka account, then create an API client in the [Eka Developer Console](https://console.eka.care) under **Manage API Credentials**. Copy the `client_id` and `client_secret`. See [Sandbox credentials](/api-reference/user-app/abdm-connect/testing#sandbox-credentials). {/* TODO: confirm: whether the same console client works against https://api.dev.eka.care, and how a client is enabled for ABDM Connect. */}
- **The sandbox server.** Calls go to `https://api.dev.eka.care`. If a playground offers a server choice, pick **Stage/Sandbox**.
- **A sandbox Aadhaar number, and the phone registered to it.** The OTP goes to that phone. {/* TODO: confirm: the sandbox test Aadhaar number and its OTP. None is published in these docs yet; add it here and to the testing page's Test data section. */}

## 1. Get an access token

This logs your client in and returns the token every later call sends.

Open [Connect Login](/api-reference/authorization/client-login) and press **Try it**. Paste this body and send it.

```json
{
  "client_id": "YOUR_CLIENT_ID",
  "client_secret": "YOUR_CLIENT_SECRET"
}
```

Copy `access_token` from the response. On each page below, paste it into the playground's **Authorization** Bearer field. `expires_in` is the token's lifetime in seconds. If a call returns `401`, run this step again.

<Accordion title="Prefer curl?">
```bash
curl -X POST "https://api.dev.eka.care/connect-auth/v1/account/login" \
  -H "Content-Type: application/json" \
  -d '{"client_id": "YOUR_CLIENT_ID", "client_secret": "YOUR_CLIENT_SECRET"}'
```
</Accordion>

## 2. Send the Aadhaar number

ABDM sends an OTP to the mobile linked to this Aadhaar.

Open [Generate OTP](/api-reference/user-app/abdm-connect/enrollment/aadhaar/initiate-registration) and press **Try it**.

```json
{
  "aadhaar_number": "YOUR_AADHAAR"
}
```

Copy `txn_id`. `hint` shows the masked number the OTP went to.

<Accordion title="Prefer curl?">
```bash
curl -X POST "https://api.dev.eka.care/abdm/na/v1/registration/aadhaar/init" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"aadhaar_number": "YOUR_AADHAAR"}'
```
</Accordion>

## 3. Verify the Aadhaar OTP

This proves the patient's identity against Aadhaar and sets the mobile the ABHA will use.

Open [Verify OTP](/api-reference/user-app/abdm-connect/enrollment/aadhaar/verify-otp) and press **Try it**. Use the Aadhaar-linked mobile for `mobile`.

```json
{
  "txn_id": "TXN_ID_FROM_STEP_2",
  "otp": "YOUR_OTP",
  "mobile": "YOUR_MOBILE"
}
```

Copy the new `txn_id`. Check that `skip_state` is `abha_create` and `abha_profiles` is empty. Any other result is a branch covered on the [workflow page](/api-reference/user-app/abdm-connect/workflows/create-abha-aadhaar-otp).

<Accordion title="Prefer curl?">
```bash
curl -X POST "https://api.dev.eka.care/abdm/na/v1/registration/aadhaar/verify" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"txn_id": "TXN_ID_FROM_STEP_2", "otp": "YOUR_OTP", "mobile": "YOUR_MOBILE"}'
```
</Accordion>

## 4. Get suggested ABHA addresses

Eka returns addresses that are free to take. This call has no body.

Open [Suggest ABHA Address](/api-reference/user-app/abdm-connect/commons/suggest-abha-address) and press **Try it**. Set the `transactionId` query parameter to `TXN_ID_FROM_STEP_3`.

Copy one entry from `suggestions`. You can type your own address instead.

<Accordion title="Prefer curl?">
```bash
curl "https://api.dev.eka.care/abdm/na/v1/registration/suggest?transactionId=TXN_ID_FROM_STEP_3" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```
</Accordion>

## 5. Check the address is free

This confirms nobody holds the address before you create it.

Open [Does ABHA Address Exist](/api-reference/user-app/abdm-connect/commons/does-health-id-exist) and press **Try it**.

```json
{
  "abha_address": "YOUR_ABHA_ADDRESS"
}
```

`exists` should be `false`. If it is `true`, pick another address and check again.

{/* TODO: confirm: whether YOUR_ABHA_ADDRESS includes the "@abdm" suffix on phr/check and create-phr. The create-phr schema example is "shyam.eka@abdm". */}

<Accordion title="Prefer curl?">
```bash
curl -X POST "https://api.dev.eka.care/abdm/na/v1/registration/phr/check" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"abha_address": "YOUR_ABHA_ADDRESS"}'
```
</Accordion>

## 6. Create the ABHA

This registers the ABHA with ABDM. It creates a real sandbox account, so send it once.

Open [Create](/api-reference/user-app/abdm-connect/enrollment/aadhaar/create-abha) and press **Try it**. Send the `txn_id` from step 3.

```json
{
  "txn_id": "TXN_ID_FROM_STEP_3",
  "abha_address": "YOUR_ABHA_ADDRESS"
}
```

Copy `profile.abha_number`, `profile.abha_address` and `eka.oid`. Later calls for this patient send `eka.oid` in the `X-Pt-Id` header.

<Accordion title="Prefer curl?">
```bash
curl -X POST "https://api.dev.eka.care/abdm/na/v1/registration/aadhaar/create-phr" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"txn_id": "TXN_ID_FROM_STEP_3", "abha_address": "YOUR_ABHA_ADDRESS"}'
```
</Accordion>

## How this fits your product

These calls are the identity step of [Register a walk-in patient and link the visit](/api-reference/user-app/abdm-connect/journeys/hip-register-patient-and-link-visit), the registration desk journey for a HIP. They cover [Milestone 1](/api-reference/user-app/abdm-connect/flows/m1). Linking the visit to the new ABHA is [Milestone 2](/api-reference/user-app/abdm-connect/flows/m2).

## If a call fails

Start with [By symptom](/api-reference/user-app/abdm-connect/errors#by-symptom) on the errors page. It covers OTPs that never arrive, lockouts and `401` responses. For each failure in this flow, the [workflow's failure table](/api-reference/user-app/abdm-connect/workflows/create-abha-aadhaar-otp#when-it-fails) says what to do. Which code each call returns is not yet confirmed, so log the code you actually receive.
