Run the happy path of every journey you support against sandbox before you go live. Each item below links the workflow's own Test it checklist, which also covers the failure cases.

## In short

- Run the happy path of every journey you support against sandbox before you go live.
- Sandbox is `https://api.dev.eka.care`; production is `https://api.eka.care`.
- Log in with your API client to get an access token, and refresh it on a `401`.
- Share a webhook endpoint that sandbox can reach with Eka before you start.
- Each item links the workflow's own Test it checklist.

## Sandbox

| Setting | Value |
|---|---|
| Sandbox base URL | `https://api.dev.eka.care` |
| Production base URL | `https://api.eka.care` |
| Authentication | Bearer token in the `Authorization` header on every call |

The base URLs are the spec's `Stage/Sandbox` and `Production` servers.

## Sandbox credentials

1. Create an Eka account and a workspace. See [Setting up your Eka account](/api-reference/authorization/getting-started#setting-up-your-eka-account).
2. In the [Eka Developer Console](https://console.eka.care), open **Manage API Credentials** and create an API client. Copy the `client_id` and `client_secret`. The secret is shown once.
3. Log in with [Client login](/api-reference/authorization/client-login) to get an access token and a refresh token.
4. When a call returns `401`, the access token has expired. Get a new one with [Refresh token](/api-reference/authorization/refresh-token-v2).
